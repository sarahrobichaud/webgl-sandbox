Sparse-Set Stores

A sparse set is the storage trick behind most practical ECS worlds in TypeScript: entity ids stay sparse and scattered, while the component values sit in a packed dense array you can loop without gaps. This lab builds that intuition with a live store you can poke.

01 The problem it solves

In ECS, an entity is just an id — say 7, 42, 108. Components live elsewhere. You need three things to be cheap:

  1. Does entity 42 have Velocity? → has(42)
  2. Give me that Velocity. → get(42)
  3. Update every Velocity. → iterate without scanning empty holes

Naïve: array indexed by entity id

velocities[42] = {…}

Lookup is O(1), but if ids go to 100_000 and only 200 have velocity, you waste a huge sparse array and iteration is painful.

Naïve: scan every entity bag

for (e of allEntities) if (e.velocity)

Iteration “works,” but you pay for entities that don’t have the component — every system, every frame.

Sparse set promise: lookup stays O(1), and iteration only touches entities that actually have the component — packed tightly in a dense array.

02 Anatomy: sparse + dense

One Store<T> per component type. Inside it, two cooperating structures:

sparse
Map (or array) from entity id → dense index. “Where in the packed list does entity 7 live?”
dense
Packed array of component values (no holes). Index i is the i-th entity that has this component.
entities
Parallel to dense: entities[i] is the entity id that owns dense[i]. Needed so iteration can report “who,” and so remove can fix the sparse map.
Static snapshot — Position store
Read a lookup out loud: get(7) → sparse.get(7) returns dense index 1 → return dense[1]. No scanning.

04 Swap-remove (the clever bit)

Deleting from the middle of a packed array would leave a hole — unless you swap the last element into the hole, then pop. That keeps dense packed and stays O(1).

Watch remove(3) on a full store
remove(id: EntityId) {
  const index = this.sparse.get(id);
  if (index === undefined) return;

  const last = this.dense.length - 1;
  const lastId = this.entities[last];

  // move last into the hole
  this.dense[index] = this.dense[last];
  this.entities[index] = lastId;
  this.sparse.set(lastId, index); // last entity’s dense index changed

  this.dense.pop();
  this.entities.pop();
  this.sparse.delete(id);
}
Don’t hold dense indices across frames. After a remove, some other entity’s index may have moved. Always go through sparse.get(id) (or get(id)).

06 A complete TypeScript Store

  

    This is a teaching implementation — enough for a game world, clear enough to memorize.
    In JS, Map for sparse is fine; engines sometimes use a big Uint32Array instead.
  


  
type EntityId = number;

class Store<T> {
  dense: T[] = [];
  entities: EntityId[] = [];
  sparse = new Map<EntityId, number>();

  get size() { return this.dense.length; }

  has(id: EntityId): boolean {
    return this.sparse.has(id);
  }

  get(id: EntityId): T | undefined {
    const i = this.sparse.get(id);
    return i === undefined ? undefined : this.dense[i];
  }

  set(id: EntityId, value: T): void {
    const existing = this.sparse.get(id);
    if (existing !== undefined) {
      this.dense[existing] = value; // overwrite in place
      return;
    }
    const index = this.dense.length;
    this.dense.push(value);
    this.entities.push(id);
    this.sparse.set(id, index);
  }

  remove(id: EntityId): void {
    const index = this.sparse.get(id);
    if (index === undefined) return;

    const last = this.dense.length - 1;
    if (index !== last) {
      const lastId = this.entities[last];
      this.dense[index] = this.dense[last];
      this.entities[index] = lastId;
      this.sparse.set(lastId, index);
    }
    this.dense.pop();
    this.entities.pop();
    this.sparse.delete(id);
  }

  /** Packed iteration — no holes */
  *entries(): IterableIterator<[EntityId, T]> {
    for (let i = 0; i < this.dense.length; i++) {
      yield [this.entities[i], this.dense[i]];
    }
  }
}


  
World = several stores

  
class World {
  positions = new Store<{ x: number; y: number }>();
  velocities = new Store<{ x: number; y: number }>();
  // boarding, meshRef, …
}

function movementSystem(world: World, dt: number) {
  for (const [id, v] of world.velocities.entries()) {
    const p = world.positions.get(id);
    if (!p) continue;
    p.x += v.x * dt;
    p.y += v.y * dt;
  }
}







  
07 Pitfalls & upgrades


  

    
      
PitfallWhy it hurtsFix

    
    
      

        Cache a dense index
        Swap-remove moves someone else into that slot
        Always resolve via entity id
      

      

        Reuse entity ids without generations
        Stale handles can revive dead entities
        Brand ids + generation counter (optional later)
      

      

        Mutate dense while iterating
        Remove mid-loop skips / double-visits
        Command buffer: queue removes, apply after systems
      

      

        One giant store of mixed stuff
        You’re back to entity bags
        One store per component type
      

      

        Expect archetype-level locality
        Values are still JS objects on the heap
        Good enough until typed arrays / archetypes are profiled needs
      

    
  


  

    
When you’re ready to upgrade

    

      Array sparse instead of Map: if entity ids are small dense integers,
      sparse: number[] (sentinel = empty) can beat Map lookups.
    

    

      Generational ids: EntityId = (index | generation << 16)
      so destroyed entities can’t be confused with recycled slots.
    

    

      Query helpers: wrap joins in world.query(Position, Velocity)
      so systems don’t hand-roll the iterate/probe pattern.
