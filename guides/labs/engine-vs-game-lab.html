01 Three layers, not two

People say “engine vs game” and forget the website shell. For a browser product, keep three buckets:

APP SHELL

Gets the player into a playthrough. Talks to the outside world.

  • login / account (behind contracts)
  • list / create playthroughs
  • menus that aren’t “inside” the world
  • loading screens, settings storage

GAME

What this product means. Survives as a playthrough document.

  • empire money & reputation
  • businesses on a world map
  • flight contracts, RP identity
  • which airport is focused

ENGINE

Reusable mechanisms. Another grid tycoon could share these.

  • frame loop, input, scenes
  • renderer / camera
  • grid world + step hooks
  • generic “tick this simulation”
Playthrough / empire / “save” are game or shell words — not engine words. The engine shouldn’t need to know you called it a campaign.

02 The reuse test

Ask one question:

“If I shipped a harbor-management game on the same engine, would this concept still make sense unchanged?”

  • Yes → engine (or maybe shell plumbing)
  • No, only airports / this empire fantasy → game
  • It’s about accounts / website / loading a document → app shell

Pick a layer.

04 Common traps

TrapWhy it hurtsBetter instinct
Engine knows “Airport” You can’t reuse the engine for another management game without lying. Engine: site / grid world. Game: airport rules on top.
Engine owns “Save / Campaign” Persistence vocabulary leaks into every future game mode. Shell loads a document; game interprets empire state; engine hosts a sim.
Renderer holds money Zooming out or going headless “deletes” the economy. Numbers live in game/sim; views only read them.
Everything is “the session” One word for login, playthrough, and frame host — confusion forever. Name shells, playthroughs, and “what’s ticking” separately when you need to.
When unsure, prefer game over engine. Promoting a concept into the engine later is easy. Digging product nouns out of engine APIs is not.

05 A default split for this product

Commit to this story (for now)

App shell — account contracts, playthrough list/create, boot into “playing.”

Game — empire, map businesses, focus, contracts, money, RP; decides which site needs a full grid.

Engine — loop, input, scenes, render; tools to host one detailed grid world and step it.
