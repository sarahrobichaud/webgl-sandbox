01 What mouse gives you

Keyboard is discrete: a finite set of codes, held or not. Mouse is continuous and discrete. Systems usually ask four things:

Query Means Use for
x, y Cursor on the canvas right now Hover, pick, UI hit-test
dx, dy Movement this frame Drag pan, look (later with lock)
wheelX/Y Scroll this frame Zoom, scrub timelines
isDown / wasPressed Button edges (same as keys) Select, drag start, context menu
Keep mouse separate from keyboard. Your LogicContext already has keyboard. Add mouse beside it — don’t jam axes into InputManager’s KeyCode API.

02 Client vs canvas coordinates

MouseEvent.clientX/Y are viewport pixels. Your canvas may be CSS-scaled (and on retina, buffer size ≠ CSS size). Always convert with getBoundingClientRect(). 

const rect = canvas.getBoundingClientRect();
const x = (e.clientX - rect.left) * (canvas.width / rect.width);
const y = (e.clientY - rect.top) * (canvas.height / rect.height);

03 Deltas & wheel — consume each frame

Unlike keyboard (diff held vs previous), deltas are accumulators. Events add into pending totals; beginFrame() publishes them for systems, then zeroes the pending buckets.

mousemove

Add movementX/Y (or Δ from last position) into #pendingDx/Dy.

wheel

Add deltaX/Y into #pendingWheel. Call preventDefault if the page shouldn’t scroll.

// inside beginFrame()
this.#dx = this.#pendingDx;  this.#pendingDx = 0;
this.#dy = this.#pendingDy;  this.#pendingDy = 0;
this.#wheelY = this.#pendingWheelY;  this.#pendingWheelY = 0;

05 Design the contract (~8 min)

Mirror the keyboard split: contract in contracts/, browser impl in input/.

// src/engine/contracts/mouse-input.contract.ts
export enum MouseButton {
  Left = 0,
  Middle = 1,
  Right = 2,
}

export interface MouseInput {
  // canvas-space position (buffer pixels)
  readonly x: number;
  readonly y: number;

  // consumed each beginFrame()
  readonly dx: number;
  readonly dy: number;
  readonly wheelX: number;
  readonly wheelY: number;

  isDown(button: MouseButton): boolean;
  wasPressed(button: MouseButton): boolean;
  wasReleased(button: MouseButton): boolean;

  beginFrame(): void;
  attach(target: HTMLElement): void;
  detach(): void;
}
Why not put buttons on InputManager? You could unify later behind actions ("Fire", "Pan"). For now, keep devices explicit — it matches how you already expose keyboard.

06 Implement browser mouse input (~15 min)

Create src/engine/input/browser-mouse-input.ts. Sketch:

export class BrowserMouseInput implements MouseInput {
  #x = 0; #y = 0;
  #dx = 0; #dy = 0;
  #wheelX = 0; #wheelY = 0;
  #pendingDx = 0; #pendingDy = 0;
  #pendingWheelX = 0; #pendingWheelY = 0;

  #down = new Set<number>();
  #prevDown = new Set<number>();
  #pressed = new Set<number>();
  #released = new Set<number>();
  #target: HTMLElement | null = null;

  get x() { return this.#x; }
  get y() { return this.#y; }
  get dx() { return this.#dx; }
  get dy() { return this.#dy; }
  get wheelX() { return this.#wheelX; }
  get wheelY() { return this.#wheelY; }

  beginFrame() {
    this.#dx = this.#pendingDx; this.#pendingDx = 0;
    this.#dy = this.#pendingDy; this.#pendingDy = 0;
    this.#wheelX = this.#pendingWheelX; this.#pendingWheelX = 0;
    this.#wheelY = this.#pendingWheelY; this.#pendingWheelY = 0;

    this.#pressed.clear();
    this.#released.clear();
    for (const b of this.#down) {
      if (!this.#prevDown.has(b)) this.#pressed.add(b);
    }
    for (const b of this.#prevDown) {
      if (!this.#down.has(b)) this.#released.add(b);
    }
    this.#prevDown = new Set(this.#down);
  }

  isDown(button: MouseButton) { return this.#down.has(button); }
  wasPressed(button: MouseButton) { return this.#pressed.has(button); }
  wasReleased(button: MouseButton) { return this.#released.has(button); }

  attach(target: HTMLElement) {
    this.detach();
    this.#target = target;
    target.addEventListener("mousemove", this.#onMove);
    target.addEventListener("mousedown", this.#onDown);
    target.addEventListener("mouseup", this.#onUp);
    target.addEventListener("wheel", this.#onWheel, { passive: false });
    target.addEventListener("contextmenu", this.#onContext);
    window.addEventListener("blur", this.#onBlur);
  }

  // #onMove: update #x/#y from rect; #pendingDx += e.movementX; etc.
  // #onDown / #onUp: mutate #down with e.button
  // #onWheel: #pendingWheelY += e.deltaY; e.preventDefault()
  // #onBlur: #down.clear()
}

  mouse.beginFrame()     ← publish dx/dy/wheel + button edges

07 Wire into Areo (~8 min)

Attach mouse to the canvas (parentElement), keyboard can stay on window. 

// components.ts
export interface LogicContext {
  deltaTime: number;
  world: GameWorld<string>;
  camera: Camera;
  keyboard: InputManager;
  mouse: MouseInput;  // ← add
}
// game-manager.ts (sketch)
#mouseInputs = new BrowserMouseInput();

constructor(config) {
  …
  this.#keyboardInputs.attach();                 // window
  this.#mouseInputs.attach(this.#parentElement); // canvas
  this.#logicContext = {
    …,
    keyboard: this.#keyboardInputs,
    mouse: this.#mouseInputs,
  };
}

#update(deltaTime: number) {
  this.#logicContext.deltaTime = deltaTime;
  this.#keyboardInputs.beginFrame();
  this.#mouseInputs.beginFrame();
  for (const logic of this.#logicComponents) {
    logic.update(this.#logicContext);
  }
}

08 Use it — pan / zoom / click (~10 min)

A good first Areo feature: LMB drag pans the camera, wheel zooms, click places a debug marker. Try the sandbox first — it’s the same queries you’ll write in CameraSystem. 

// camera-system.ts sketch
update({ camera, mouse, deltaTime }: LogicContext) {
  if (mouse.isDown(MouseButton.Left)) {
    const p = camera.position;
    // tune scale: dx in canvas px → world units
    camera.setPosition({
      x: p.x - mouse.dx * 0.01,
      y: p.y,
      z: p.z - mouse.dy * 0.01,
    });
  }

  if (mouse.wheelY !== 0) {
    // wheelY > 0 typically means “scroll down” → zoom out
    zoom *= mouse.wheelY > 0 ? 0.9 : 1.1;
    camera.setZoom(zoom);
  }

  if (mouse.wasPressed(MouseButton.Right)) {
    // one-shot: spawn marker at mouse.x / mouse.y (after unproject — later)
  }
}

09 Gotchas

  • CSS size ≠ buffer size. Always scale with canvas.width / rect.width when storing x/y.
  • movementX/Y vs position delta. Prefer movementX/Y for drag — they’re relative and still work near screen edges. Position-diff breaks if the cursor leaves the element mid-drag.
  • Stuck buttons: if the user mouseups outside the canvas, you may miss mouseup. Also listen on window for mouseup, or clear on pointerleave / blur.
  • Wheel units vary across devices (deltaMode can be pixels, lines, or pages). Treat magnitude as “rough intent,” tune a sensitivity constant, don’t assume 100 means anything universal.
  • Don’t put listeners in systems — same rule as keyboard.
Anti-pattern: reading mousemove inside CameraSystem.update and applying pan immediately. You’ll fight the frame loop and double-apply on multi-system reads. Accumulate → beginFrame → one read per system tick.

Free-cursor mouse on the canvas: position + frame deltas + wheel + 3 buttons. No pointer lock, no raycasts yet. Enough for editor-style camera control next to WASD.

Stretch (after the hour)

  • Pointer lock: canvas.requestPointerLock() on click; use only movementX/Y for FPS look; Escape exits.
  • Screen → world: unproject mouse.x/y through the inverse view-projection to place entities on the XZ floor.
  • Action map: bind "Pan" → LMB, "Zoom" → wheel, so devices stay swappable.
